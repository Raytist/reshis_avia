# Решись Авиа — прогноз продаж билетов

Блок «Разработка» кейса «Динамическое ценообразование авиабилетов» (турнир «Решись»).
**Вариант C**: веб-страница с формой, которая отправляет данные через JavaScript на backend API,
а расчёт выполняется на сервере (Python, Flask).

## Что умеет

**Обязательная функция.** Пользователь вводит пункт отправления, пункт назначения, дату вылета и цену.
Сервис находит рейс в прогнозе и показывает число мест и прогноз продаж:

```
желают = 0.5_base_demand − price_sensitivity × (цена − base_price)
купят  = min(seats, max(0, желают))
```

**Дополнительные функции из списка кейса**

| № | Функция | Как сделано |
|---|---|---|
| 1 | График распределения спроса при введённой цене | девять сценариев 0.1–0.9 по той же формуле; медиана совпадает с «желают»; пунктир — число мест; штриховка — часть спроса, на которую не хватит мест |
| 2 | Регистрация | логин и пароль; пароль хранится только в виде хеша (werkzeug, PBKDF2), пользователи — в SQLite |
| 3 | Авторизация | вход и выход, сессия в защищённой cookie; без входа прогноз недоступен (API отвечает 401) |
| 4 | Размещение на хостинге | готовые `deploy/timeweb/.htaccess` и `index.wsgi` для виртуального хостинга Timeweb, инструкция ниже |

**Собственные идеи**

- **Бегунок цены**: прогноз и график пересчитываются сразу, пока двигаешь цену.
- **Вероятность распродать рейс**: по квантилям прогноза видно, с какой вероятностью желающих будет больше, чем мест.
- **Две рекомендованные цены**: цена из ML-модели для медианного сценария и цена, при которой **средняя** прибыль
  по всем девяти сценариям наибольшая. Вторая учитывает риск: и недобор, и нехватку мест.
- **Календарь месяца**: по каждому дню — рекомендованная цена и вероятность распродать рейс по базовой цене;
  цвет дня показывает силу спроса, нажатие на день считает его.
- **История запросов** пользователя (последние 10).
- Понятные сообщения об ошибках: обратное направление, неизвестный маршрут, дата вне прогноза, неверная цена.
- Оформление в едином стиле с нашим сервисом «Олимп» (шрифт Onest, синий акцент, мягкие поля и кнопки-пилюли) и вёрстка для телефона.

## Запуск в Docker (основной способ)

```bash
docker compose up -d --build      # сайт: http://localhost:8080
```

Сборка образа сначала прогоняет тесты: если хоть один упал, образ не соберётся. Внутри — gunicorn
(2 процесса), пользователь без прав root, проверка здоровья по `/api/routes`. База пользователей и
секретный ключ хранятся в томе `instance`, поэтому переживают перезапуск. Свой ключ: `SECRET_KEY=... docker compose up -d`.

## Запуск без Docker

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows; на macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt -r requirements-dev.txt
python app.py                   # http://127.0.0.1:5000
```

Тесты (формула, граничные случаи, регистрация, вход, доступ к API): `python -m pytest -q`.

## Свой прогноз из ML-части

Положите файл `ФИО_my_forecast.csv` в папку `data/`: сервис сам возьмёт файл, имя которого заканчивается на

## Размещение в Timeweb Cloud App Platform (Docker)

По [документации Timeweb Cloud](https://timeweb.cloud/docs/apps/deploying-with-dockerfile):

1. App Platform → «Создать» → подключите GitHub и выберите репозиторий `Raytist/reshis-avia`, ветку `main`.
2. Фреймворк — **Dockerfile** (лежит в корне, путь к директории оставьте пустым). Порт платформа возьмёт из
   `EXPOSE 8000`.
3. Переменные окружения: `SECRET_KEY` — длинная случайная строка (чтобы входы не сбрасывались при перезапуске).
4. Дополнительно: путь проверки здоровья — `/api/routes`.
5. Нажмите «Запустить деплой» и дождитесь конца сборки на вкладке «Деплой» — сайт откроется по техническому
   домену из «Дашборда». Каждый `git push` в `main` пересобирает сайт автоматически.

Хранилища в App Platform нет, поэтому зарегистрированные пользователи сбрасываются при новом деплое —
для демонстрации жюри это не мешает.

## Размещение на виртуальном хостинге Timeweb (без Docker)

Виртуальный хостинг (тот, что с бесплатным периодом в условиях кейса) Docker не запускает, поэтому для него
есть отдельный вариант.

Схема по [документации Timeweb](https://timeweb.com/ru/docs/virtualnyj-hosting/prilozheniya-i-frejmvorki/flask/):
Apache + mod_wsgi, точка входа `index.wsgi` в `public_html`. Код сайта лежит **вне** `public_html`, чтобы база
пользователей и секретный ключ не открывались по ссылке. Сайт проверен на Python 3.10 (как на серверах Timeweb
с Ubuntu 22.04).

1. Оформите виртуальный хостинг с бесплатным периодом и откройте в панели **SSH-консоль** (или подключитесь по SSH).
   Узнайте версию Python: `python3 --version` (на Ubuntu 22.04 — 3.10).
2. Создайте виртуальное окружение и поставьте Flask:
   ```bash
   cd ~ && python3 -m venv venv && venv/bin/pip install flask
   ```
3. Загрузите код в домашнюю папку (рядом с `venv`, **не** в `public_html`), например так:
   ```bash
   cd ~ && git clone https://github.com/Raytist/reshis-avia.git
   ```
   или через файловый менеджер панели из `ФИО_разработка.zip`.
4. Скопируйте файлы входа в папку сайта и сделайте `index.wsgi` исполняемым
   (`имя_сайта` — папка сайта в панели, обычно совпадает с доменом):
   ```bash
   cp ~/reshis-avia/deploy/timeweb/.htaccess ~/reshis-avia/deploy/timeweb/index.wsgi ~/имя_сайта/public_html/
   chmod 755 ~/имя_сайта/public_html/index.wsgi
   ```
5. В `public_html/index.wsgi` замените в двух путях `u/user` на первую букву логина и логин, а `python3.10` —
   на версию из шага 1. Удалите из `public_html` заглушку `index.html`, если панель её создала.
6. Откройте домен: должна появиться страница входа. Секретный ключ создастся сам в `~/reshis-avia/instance/`
   (или задайте переменную окружения `SECRET_KEY`).

Для других хостингов с Phusion Passenger есть `passenger_wsgi.py` (объект `application`).
